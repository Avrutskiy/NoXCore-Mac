NoXCore-Mac: additive Mac implementation
=======================================

Requires Apple Silicon, macOS 26+, Xcode 26 Command Line Tools, CMake 3.25+, Ninja,
glslang and SPIRV-Cross. The deployment target follows libc++ floating-point from_chars.

  brew install cmake ninja glslang spirv-cross
  cmake -S . -B build/macos-arm64 -G Ninja -C macos/cache.cmake
  cmake --build build/macos-arm64 --target noxsdl_bundle -j 4

Set macos/version.txt to the intended release version before building the release artifact.
The macOS workflow checks both version fields in the signed app and compares release tags.

Packaging verifies a fresh staged bundle before replacing the previous build, so
removed resources do not survive a rebuild. Keep user content outside the build bundle.

The first configure downloads the pinned upstream dependencies. The app is
build/macos-arm64/NoX Core.app. It is ad-hoc signed, not notarized. It includes fonts,
licenses and mods, but no original game data. NOX_BUILD_VIDEOTOOLS is OFF for this build.

Game Mode
---------
The bundle declares public.app-category.games and LSSupportsGameMode=true. macOS
activates Game Mode when the app enters native full screen; a regular window does not
activate it. Launch through Finder or Launch Services, including when passing arguments:

  open "build/macos-arm64/NoX Core.app" --args --game-dir "/path/to/Nox"

Launching Contents/MacOS/noxcore directly from Terminal may prevent Game Mode activation.
If a player previously disabled Game Mode for this app, macOS remembers that choice;
they can turn it back on in the Game Overlay (Command-Esc) while in full screen.
The opt-in does not change the selected display mode.

Data and writable state
-----------------------
Place the app beside your installed game data, or place the data in
~/Library/Application Support/NoXCore/GameData. Bundled Contents/Resources/GameData
is also recognized. --game-dir overrides discovery; NOX_DATA is checked before the
bundle and usual folders. The launcher passes the selected directory to upstream.

Settings and saves use ~/Library/Application Support/NoXCore/UserData, with saves in
Save/. --user-dir overrides this Mac location. Migration preserves existing user files
and does not resurrect deleted characters. Overlapping save-import directories are
rejected before copying, including paths reached through symlinks. Input Config Reset reads the user nox.cfg;
Defaults reads the installed game default.cfg.

For backups or transfers, quit the game and copy the entire UserData/Save directory,
including its subfolders. Preserve the current directory before restoring a backup.
Copy nox.cfg and noxcore.cfg separately to retain settings. Replacing the app does not
replace this per-user data. Finder's Go > Go to Folder (Shift-Command-G) opens these paths.
An explicit --save-dir overrides the default and skips automatic save import.

SDL_GetPrefPath selects the persistent per-user location; on macOS this is Application
Support. This keeps settings and progress independent of asset-folder permissions and
app updates.

Mods live in UserData/Mods. Bundled editable mods are imported once, without merging
into existing projects or restoring deleted projects. Bundled reference mods (such as
Deep Delve) follow app updates; the editor opens those as separate editable copies.
An editable project with the same folder name is preserved. Back up
Mods along with Save when keeping custom work. --mods-dir selects another mod folder
and skips bundled import.

The launcher supplies --save-dir, --mods-dir, --map-cache and --log defaults through upstream's
existing options. Explicit values retain precedence. The default log is
~/Library/Application Support/noxcpp/noxsdl/noxcore-log.txt. These defaults keep settings, saves, map caches and logs outside
the signed bundle. Launching its Contents/MacOS/noxcore executable also uses this setup.

Source structure
----------------
Upstream PRs #22 and #28 supply three Mac policy functions: a settings directory,
additional window-creation flags and an optional usable render area. Other platforms
use inline defaults. The upstream default implementations and shaders remain the
normal build. The fork's implementation changes
are confined to macos/ and its Mac workflow; shared engine and client sources match upstream.

macos/sdl_metal_upload.cmake backports SDL commit 32f9c098 (Metal upload row stride)
to the pinned SDL 3.4.16 source. The game keeps its normal 256-byte atlas layout.
The backport is idempotent and stops configuration if the source no longer matches;
remove it when the pinned SDL includes the fix. When sharing a FetchContent source
cache with other builds, give the Mac build its own SDL source directory.

macos/cache.cmake uses CMake's standard project-injection API to load client.cmake after
upstream's targets exist. CMake's SOURCES target property replaces backend_hooks.cpp
and gpu_shader_code.cpp with the Mac implementations; configuration fails if either
expected source is missing. It also adds the launcher, Metal shaders and app packaging. SDL's
standard callback entry point is emitted by launcher.cpp, which prepares state and calls
the original SDL_AppInit. Mac wrappers around SDL_AppEvent and SDL_AppIterate filter
pointer input and update confinement after upstream layout and mouse-owner changes.
SDL_AppQuit remains upstream. On Cocoa the packaged client uses the icon declared in
Info.plist. A standalone client or a bundle missing its icon uses the embedded ICO.
No existing NoXCore source file is patched or copied into a modified build tree.

SDL's render safe area fits the game and movie output below the notch. Pointer bounds
use window points, rounding inward when converting from render pixels. Queued relative
mouse events are clamped before game-coordinate mapping; absolute presses and wheel
events outside the usable area are ignored, while releases still reach the game.
Embedded editor play views retain ownership of their own confinement rectangles.

Both editors get their safe work area through a per-context ImGui NewFramePost hook.
CMake renames only the bundled SDL backend initializer so the Mac adapter can call it
and install the hook. This uses the pinned ImGui context-hook API; recheck it when
upgrading ImGui. The bundle leaves macOS's display compatibility policy unchanged.

Checks
------
Asset-free startup and migration tests:

  cmake -S macos/tests -B build/mac-tests -G Ninja -DCMAKE_BUILD_TYPE=Release
  cmake --build build/mac-tests
  ctest --test-dir build/mac-tests --output-on-failure

Asset-free safe-area checks (requires the full Mac client build and Ninja):

  cmake -S . -B build/macos-arm64 -G Ninja -C macos/cache.cmake -DNOX_BUILD_NOTCH_TESTS=ON -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
  cmake --build build/macos-arm64 --target noxsdl_bundle nox_notch_policy_tests nox_notch_display_smoke -j 4
  ctest --test-dir build/macos-arm64 -R mac_notch --output-on-failure

These cover Retina conversion, queued input, confinement ownership, game/editor
handoffs, rendered margins, movie viewport restoration and ImGui work-area refresh.
The integration harness links production objects with SDL's dummy driver and controlled
frame delegates; it does not exercise a full gameplay session. It reuses Ninja's link
command and the pinned SDL private test seam, without changing production artifacts.
For a native Metal check, run the following in a Mac graphics session. It briefly
enters desktop and exclusive fullscreen, prints the display's actual safe bounds and
checks rendered pixels. A notched display is needed to validate a nonzero native inset.

  build/macos-arm64/nox_notch_display_smoke

On a Mac graphics session, compile and run GPU checks:

  cmake -S . -B build/macos-arm64 -G Ninja -C macos/cache.cmake -DNOX_BUILD_METAL_TESTS=ON
  cmake --build build/macos-arm64 --target nox_metal_smoke nox_gpu_atlas_tests -j 4
  build/macos-arm64/nox_metal_smoke
  build/macos-arm64/nox_gpu_atlas_tests

These check shader creation/readback and Metal atlas uploads with the upstream
256-byte atlas alignment. Test commands and cheats stay OFF in the shipped client.

Maintenance
-----------
Keep Mac implementation, packaging and tests in Mac files. Shared engine and client
sources must match the upstream base. PRs #22 and #28 are part of that base; the Mac
safe-area policy lives entirely in this fork.
Preserve release tags when updating main; release assets must match their tagged source.
